# Project Overview

This project consists of two desktop applications written in Go using Fyne:

1. **Watcher Client**

   * Monitors folders
   * Uploads files automatically to server APIs

2. **Central Upload Server**

   * Receives uploaded files
   * Validates files
   * Stores files into destination folders
   * Monitors connected watchers

The system must be redesigned into a scalable centralized document ingestion system.

---

# Final Architecture

```text
WATCHER CLIENT
├── Monitor multiple folders
├── Each folder has its own API URL
├── Auto upload files
├── Retry failed uploads
├── Send heartbeat to server
└── Register watcher to server

                ↓

CENTRAL SERVER
├── Dynamic Upload API
├── Endpoint Manager
├── File Validation
├── Destination Folder Routing
├── Watcher Monitoring
├── Upload Logs
├── Authentication
└── Dashboard UI
```

# WATCHER APPLICATION REQUIREMENTS

# 1. Remove File Validation from Watcher

The watcher must NO LONGER:

* filter file extensions
* validate filenames
* determine allowed files

The watcher must:

* upload all detected files
* let the server decide whether the file is accepted or rejected

---

# 2. Multi Folder Monitoring with Different API URLs

The watcher must support multiple monitored folders.

Each monitored folder must have its own API URL.

Example:

| Folder Path    | API URL                                                                    |
| -------------- | -------------------------------------------------------------------------- |
| D:/scan/pebjf  | [http://localhost:8080/upload/pebjf](http://localhost:8080/upload/pebjf)   |
| D:/scan/report | [http://localhost:8080/upload/report](http://localhost:8080/upload/report) |

---

# 3. Watcher Database Schema

Use SQLite.

Create table:

```sql
CREATE TABLE watch_paths (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    folder_path TEXT,
    api_url TEXT,
    enabled INTEGER DEFAULT 1
);
```

---

# 4. Watcher UI Requirements

The UI must provide:

* Add Monitoring
* Edit Monitoring
* Delete Monitoring
* Enable/Disable Monitoring

Display monitored folders in a table:

| Folder | API URL | Status |
| ------ | ------- | ------ |

---

# 5. Watcher Upload Flow

When a new file appears:

1. Detect which monitored folder the file belongs to
2. Find the API URL associated with that folder
3. Upload the file to the correct endpoint

---

# 6. Wait Until File is Stable Before Upload

Before uploading:

* ensure file size is stable
* prevent corrupted uploads

Implement logic similar to:

```go
func waitFileStable(path string)
```

---

# 7. Retry Failed Uploads

If upload fails:

* do not delete the file
* retry automatically later

---

# 8. Delete File Only After Successful Upload

After successful upload:

* delete local file

If upload fails:

* keep file locally

---

# 9. Watcher Registration System

When watcher starts:

Send request:

```http
POST /watcher/register
```

Payload:

```json
{
  "watcher_uuid": "WATCHER-XXXX",
  "watcher_name": "LAB-PC-01",
  "paths": [
    {
      "folder": "D:/scan/pebjf",
      "endpoint": "/upload/pebjf"
    }
  ]
}
```

---

# 10. Heartbeat System

Watcher must send heartbeat every 30 seconds.

Endpoint:

```http
POST /watcher/heartbeat
```

Payload:

```json
{
  "watcher_uuid": "WATCHER-XXXX"
}
```

---

# 11. Watcher Unique Identifier

Each watcher must have a persistent UUID.

Example:

```text
WATCHER-3F91A
```

Store UUID in SQLite settings.

---

# SERVER APPLICATION REQUIREMENTS

# 1. Dynamic Upload Endpoints

The server must support dynamic endpoints.

Examples:

```text
/upload/pebjf
/upload/report
/upload/archive
```

The endpoint determines:

* allowed file type
* destination folder
* upload behavior

---

# 2. Endpoint Database Schema

Use SQLite.

Create table:

```sql
CREATE TABLE upload_endpoints (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT,
    endpoint TEXT UNIQUE,
    allowed_extension TEXT,
    destination_folder TEXT,
    max_size_mb INTEGER,
    enabled INTEGER DEFAULT 1
);
```

---

# 3. Server Upload Validation

Validation must happen ONLY on the server.

The server must validate:

* file extension
* MIME type
* max file size

Reject invalid uploads.

---

# 4. Multi Destination Folder Support

Each endpoint must have its own destination folder.

Example:

| Endpoint       | Destination Folder |
| -------------- | ------------------ |
| /upload/pebjf  | D:/docs/pebjf      |
| /upload/report | D:/docs/report     |

---

# 5. Auto Create Destination Folder

If destination folder does not exist:

* automatically create it

Use:

```go
os.MkdirAll(...)
```

---

# 6. Prevent Filename Overwrite

Implement automatic rename strategy.

Example:

```text
20260518_153000_report.pdf
```

Possible strategies:

* timestamp
* UUID
* incremental numbering

---

# 7. JSON API Response

Success response:

```json
{
  "success": true,
  "message": "Uploaded successfully"
}
```

Reject response:

```json
{
  "success": false,
  "message": "Extension not allowed"
}
```

---

# 8. Watcher Monitoring System

The server must track:

* connected watchers
* online/offline status
* monitored folders
* endpoints used
* last heartbeat timestamp

---

# 9. Watcher Database Schema

Create table:

```sql
CREATE TABLE watchers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    watcher_uuid TEXT,
    watcher_name TEXT,
    ip_address TEXT,
    last_seen DATETIME,
    status TEXT
);
```

---

# 10. Upload Logs

Create table:

```sql
CREATE TABLE upload_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    watcher_uuid TEXT,
    endpoint TEXT,
    filename TEXT,
    status TEXT,
    uploaded_at DATETIME
);
```

---

# 11. Authentication

Support API authentication using Bearer Token.

Example:

```http
Authorization: Bearer TOKEN
```

Authentication can be:

* per watcher
* per endpoint
